## 🇬🇧 English

2048 Merge is the classic sliding-tile puzzle. A swipe moves every tile one way, and equal numbers merge into one when they collide. Play on a 3×3, 4×4, 5×5 or 6×6 board. There is no hard finish: play goes on past 2048. A game ends only when the board is full and no moves are left.

All graphics and sound effects are generated by code at runtime, and an original soundtrack, **"2048 Quiet Tiles"**, plays underneath. Move hints come from the game's own search engine, written in Rust. The arm64 APK is about 30 MB, almost all of it the engine and the music.

### Features

| | |
|---|---|
| 🎯 **Faithful 2048 rules** | One merge per tile per move, spawns 2 (90%) or 4 (10%) |
| 🔲 **Four board sizes** | 3×3, 4×4, 5×5 and 6×6, picked next to "New game" and remembered. Records are kept per size, overall and **without help** (no undo, no hints) |
| 💡 **Move hints, three strengths** | The bulb suggests a move by nudging the tiles that way; after 15 idle seconds it lights up by itself. **Simple** answers at once, **Medium** thinks for up to a second, **Smart** goes as deep as the phone manages in up to 15 seconds and stops early once its answer is settled. A ring on the bulb shows the search from the first tap; tapping again or moving calls it off |
| ↩️ **Undo, your way** | 0 to 5 steps back (default 1). The move plays backwards: tiles glide home and merged tiles split apart. The "No moves left" card can undo the losing move |
| 📊 **Statistics** | Games played, average score, best score, best without help, best tile, longest game, total moves and time played, overall or per board size. A game counts once it is lost, or after ten moves when you start a new one |
| 💾 **Saves that survive** | Everything is saved after every move. Writes are atomic, the previous save is kept as a backup, and a damaged file is set aside, never overwritten |
| 🔁 **Your data, your choice** | Save progress to a file and load it on another phone; reset statistics, records or both, for every size or one, behind two confirmations |
| 🎉 **Milestones** | 128 / 256 / 512 / 1024 / 2048 / … bring a banner, confetti and a chime, once per game |
| 📱 **Phones and tablets, any orientation** | Portrait and landscape layouts for every screen; a swipe can start anywhere between the scores and the buttons |
| 🌗 **Themes: auto, light and dark** | Auto follows the phone, even while you play; both themes are built on the same color roles, and text keeps at least 4.5:1 contrast |
| ♿ **Text size and reduced motion** | Text follows the phone's font size (up to 130%) or a fixed 100/115/130%; Reduce motion keeps the tiles sliding and turns confetti, rings, pulses and bounces into plain fades |
| 🖼️ **Graphics quality** | Low (720p), medium (1080p) or high (up to 2K), never above the screen's own resolution |
| 🌐 **English & Russian** | Picked from the system language (Russian also for neighbouring countries), switchable in settings |
| 📳 **Haptics that grow with the tiles** | Merging 2s is silent; from 4s up to 65536 every merge is a step stronger, and a lost game ends with soft waves. Follows the phone's own vibration settings |
| 🎵 **Original music** | "2048 Quiet Tiles"; separate 7-step volume for music and effects |
| 🔋 **Battery friendly, 60–144 Hz** | Animation runs as fast as the screen allows or at a cap you choose; a still screen redraws nothing and lets the display drop to its idle rate, and the display sleeps two minutes after your last touch |

### Install

- **RuStore:** [2048 Merge](https://www.rustore.ru/catalog/app/com.mahiron.merge2048) – updates arrive by themselves.
- **GitHub:** open the [latest release](https://github.com/Mahiron-hq/2048/releases/latest) and download an APK:
  - **`2048-Merge-vX.Y.Z-arm64-v8a.apk`** for virtually every phone and tablet from recent years. If unsure, take this one.
  - **`…-armeabi-v7a.apk`** for older 32-bit devices where the first one won't install.
  - **`…-universal.apk`** contains both (it is the file RuStore gets), at twice the size.

  Open the file on your device and allow installs from that source if Android asks. From a computer: `adb install -r 2048-Merge-vX.Y.Z-arm64-v8a.apk`.

The `.aab` file in the release is the bundle for Google Play; it does not install on a phone directly. Every release carries checksums and a signed provenance attestation, see [SECURITY.md](SECURITY.md).

> Requires Android 8.0 (API 26) or newer. New versions install over old ones and keep your records, statistics and settings.

### How to play

- **Swipe** in any direction to move all tiles. Equal numbers merge, and their sum is added to your score.
- Pick the **board size** with the button left of **New game** in the menu.
- **The bulb** shows a suggested move: the tiles lean that way twice. The move itself is yours to make. Hold the bulb for a second to switch its strength right there, or set it in **Settings → Game settings**.
- **Undo** plays the last move backwards. The number on the button shows how many steps you can still take back.
- Android **Back** goes to the menu, and from the menu sends the game to the background. Your game is saved either way.
- **Settings:** sound and music with volume sliders, vibration, theme, language, text size, reduced motion, graphics quality, FPS counter and limit; hints and their strength, undo depth; progress file, resets; About.

### Performance and battery

Measured with version 1.3.1 on an **Infinix NOTE 50 Pro** (Android 16, MediaTek MT6789, Mali-G57, screen at 120 Hz) and a **Redmi Note 10S** (Android 13, MediaTek MT6785, Mali-G76, 60 Hz). CPU time is the game's share of one core; every phase, the battery estimate, memory and the method are in [docs/PERFORMANCE.md](docs/PERFORMANCE.md).

| | Infinix: frames/s, CPU | Redmi: frames/s, CPU |
|---|---|---|
| Menu, untouched | 0, 7% | 0, 8% |
| New board, untouched (arrows breathing) | 30, 52% | 30, 63% |
| Playing, 2 moves a second | 103, 86% | 55, 75% |
| FPS counter on, no cap | 120, 100% | 60, 87% |
| … cap 60 | 60, 77% | 60, 88% |
| … cap 30 | 30, 50% | 30, 62% |

- **A still screen costs almost nothing.** It draws no frames, and two seconds after your last touch the game lets the display drop to its idle rate (the Infinix goes from 120 to 60 Hz, as it does for the system's own apps) and wakes less often. Most of what remains is the music. The breathing arrows on a new board draw at 30 frames a second, not at the screen's 60–120.
- **Battery:** Android's own estimate on the Redmi puts an hour of play at about 90 mAh at minimum brightness, under 2% of its battery, and 87% of that is the screen.
- **Hints:** Simple answers in about 10 ms. Medium takes a median of 0.1–0.85 s and at most about 0.9 s: it stops early when the next level of depth cannot finish within its second. Smart takes from a fraction of a second up to its 15-second cap, a median of 4–13 s. The Rust engine is about 40 times faster than 1.3.0's GDScript solver on one core.
- **Size:** the arm64 APK is 29 MB to download and 99 MB installed; the game reaches its first frame in about 0.4 s (Infinix) and 0.75 s (Redmi). Memory: about 245–270 MB.
- The frame cap paces evenly when the screen's rate is a multiple of it: 60 on 120 Hz screens, 30 everywhere; a cap above the screen's rate changes nothing.

### Build from source

You need **Godot 4.7.2** (standard), its export templates, **JDK 17**, the **Android SDK** (platform 36, build-tools 36.1.0, NDK 29.0.14206865), **Rust 1.95** with the targets `aarch64-linux-android` and `armv7-linux-androideabi`, [`cargo-ndk`](https://github.com/bbqsrc/cargo-ndk) and Python 3. Point Godot's editor settings at the SDK and JDK.

```bash
git clone https://github.com/Mahiron-hq/2048.git
cd 2048
python tools/build_native.py host        # the Rust hint engine for this computer (editor and tests)

# Android packages: the signing key comes from the environment, the repo holds no secrets
export ANDROID_HOME=/path/to/sdk ANDROID_NDK_HOME=$ANDROID_HOME/ndk/29.0.14206865 GODOT=godot
export GODOT_ANDROID_KEYSTORE_RELEASE_PATH=/path/to/release.jks
export GODOT_ANDROID_KEYSTORE_RELEASE_USER=alias
export GODOT_ANDROID_KEYSTORE_RELEASE_PASSWORD=secret
python tools/export_android.py           # arm64, armeabi-v7a and universal APKs and the AAB in build/
```

`export_android.py` is what the release workflow runs too: it builds the Rust library for both ABIs, installs the Gradle template with pinned checksums, exports, signs the APKs with schemes v2 and v3 and checks each package's certificate, version and native code.

You can play and debug on a PC with `godot --path .` (mouse drag = swipe, arrows/WASD, `Z` to undo, `H` for a hint, `Esc` for back; resize the window to try landscape).

Tests:

```bash
cd native && cargo test && cd ..                                  # the hint engine: rules (property tests), search, levels
godot --headless --path . --script res://tests/run_tests.gd       # rules, sizes, undo, saves, statistics, translations, contrast, hints, music seam
godot --headless --path . --script res://tests/ui_smoke.gd        # the whole UI through real input, incl. landscape and quality levels
godot --path . --script res://tests/layout_shots.gd               # every screen, both themes, six screen shapes (needs a GPU)
python tools/device_bench.py <serial> build/2048-Merge-vX.Y.Z-bench.apk out.json   # on-device measurements
```

Store and README screenshots come from real games ([`tools/make_screenshots.gd`](tools/make_screenshots.gd)); banners, icon and video are generated by the other scripts in `tools/`.

### Continuous integration

- **[Tests](.github/workflows/ci.yml)** on every push to main and every pull request: the Rust engine's format, lints (warnings as errors), build and tests; `gdlint`; a version consistency check; the Godot test suites on Linux with the native engine, failing on any script error or leak.
- **[Release](.github/workflows/release.yml)** on a tag `vX.Y.Z`: the tests, then a build job without write access that produces all APKs and the AAB with [`tools/export_android.py`](tools/export_android.py), a start check of the universal APK on an Android emulator, and only then a publish job that attests the packages and attaches them to the release with notes from [CHANGELOG.md](CHANGELOG.md).
- **[Pages](.github/workflows/pages.yml)** publishes the [privacy policy](https://mahiron-hq.github.io/2048/privacy/) from `PRIVACY.md`.
- **Supply chain:** every action is pinned to a commit SHA (Dependabot proposes updates, also for the Rust crates), Godot and its templates are checked against their SHA-512 sums, Gradle and every Maven artifact against pinned checksums, Rust builds use the locked dependency versions, and packages must carry the release certificate. The signing key lives only in the `release` environment's secrets.

### How it works

- **`scripts/core/board.gd`**: pure board logic for any size from 3×3 to 6×6. A move reports slides, merges and the spawn; tiles keep stable ids, a bounded undo history replays moves backwards, and saves are parsed strictly.
- **`native/`**: the hint engine in Rust. `core` holds the board, the row heuristic and an expectimax search that deepens one level at a time, shares the spawns under the root moves out to worker threads with their own transposition tables, refines its probability cut-off when time is left, and stops on the budget, a cancel or a settled answer. `gdext` exposes it to Godot as `HintEngine` through godot-rust; `scripts/core/hint_runner.gd` falls back to the GDScript solver where the library is missing.
- **`scripts/core/save_store.gd`**: atomic JSON persistence with a backup and recovery, records and statistics per board size, settings, the game in progress with its undo history; older saves migrate automatically.
- **`scripts/ui/design.gd`, `palette.gd`, `tile_art.gd`, `motion.gd`**: the design system: tokens, color roles, one tile renderer, text scale and reduced motion. Overview: [docs/DESIGN.md](docs/DESIGN.md).
- **`scripts/ui/board_view.gd`**: move and undo animation over pooled tile nodes. A swipe that lands mid-animation fast-forwards it, so input is never lost.
- **`scripts/app.gd`**: screen routing, orientation-aware scaling (the short side is always 720 units), theme and language, play time, display keep-awake, saves in the background.
- **`scripts/platform/`**: Android over JNI: haptics through the system `Vibrator` (touch feedback for taps, media for merges), refresh rate requests, font scale, "remove animations", sending the app to the background.
- **`locale/*.po`**: the interface strings, with plural forms.
- The Compatibility renderer (OpenGL ES 3) gives the widest support on budget devices.

### Limitations

- **iOS.** The project is cross-platform and an iOS preset exists, but an `.ipa` needs macOS, Xcode and an Apple Developer account, and the hint engine has no iOS build yet.
- The explicit refresh rate request works on Android 11+. On Android 8–10 the OS picks the rate; the frame cap works everywhere.
- No app can exceed the refresh rate chosen in the phone's display settings, and some skins limit it further per app (Infinix XOS, for example, has a per-app list). The game still asks for the panel's maximum, so it gets the highest rate the phone allows.

### Как играть

- **Свайп** в любую сторону сдвигает все плитки. Одинаковые числа сливаются, и их сумма добавляется к счёту.
- **Размер поля** выбирается кнопкой слева от «Новая игра» в меню.
- **Лампочка** показывает подсказанный ход: плитки дважды подаются в эту сторону. Сам ход делаете вы. Если удержать лампочку секунду, рядом появятся три уровня ума, чтобы переключить его прямо в игре; ещё он задаётся в **Настройках → Настройки игры**.
- **Отменить** проигрывает последний ход назад. Число на кнопке показывает, сколько отмен ещё доступно.
- Кнопка **«Назад»** на Android ведёт в меню, а из меню сворачивает игру. Партия при этом сохраняется.
- **Настройки:** звук и музыка с ползунками громкости, вибрация, тема, язык, размер текста, уменьшение движения, качество графики, счётчик и ограничение FPS; подсказки и их ум, количество отмен; файл прогресса, сброс; «О программе».

### Производительность и батарея

Замеры версии 1.3.1 на **Infinix NOTE 50 Pro** (Android 16, MediaTek MT6789, Mali-G57, экран 120 Гц) и **Redmi Note 10S** (Android 13, MediaTek MT6785, Mali-G76, 60 Гц). Процессорное время – доля одного ядра, которую тратит игра; все фазы, оценка батареи, память и методика – в [docs/PERFORMANCE.md](docs/PERFORMANCE.md) (на английском).

| | Infinix: кадров/с, CPU | Redmi: кадров/с, CPU |
|---|---|---|
| Меню, без касаний | 0, 7% | 0, 8% |
| Новое поле, без касаний (стрелочки дышат) | 30, 52% | 30, 63% |
| Игра, 2 хода в секунду | 103, 86% | 55, 75% |
| Счётчик FPS, без ограничения | 120, 100% | 60, 87% |
| … ограничение 60 | 60, 77% | 60, 88% |
| … ограничение 30 | 30, 50% | 30, 62% |

- **Неподвижный экран почти ничего не стоит.** Кадры не рисуются, а через две секунды после последнего касания игра отпускает дисплей на частоту покоя (Infinix переходит со 120 на 60 Гц, как и для системных приложений) и реже просыпается. Остаток – в основном музыка. Дышащие стрелочки на новом поле рисуются с 30 кадрами в секунду, а не с частотой экрана 60–120.
- **Батарея:** по собственной оценке Android на Redmi час игры стоит около 90 мА·ч при минимальной яркости – меньше 2% батареи, и 87% из них приходится на экран.
- **Подсказки:** Простой отвечает примерно за 10 мс. Средний думает в среднем (медиана) 0,1–0,85 с и не дольше примерно 0,9 с: он останавливается раньше, когда следующий уровень глубины не успеет за секунду. Умный думает от доли секунды до предела в 15 секунд, в среднем 4–13 с. Движок на Rust примерно в 40 раз быстрее решателя 1.3.0 на GDScript на одном ядре.
- **Размер:** APK для arm64 – 29 МБ для скачивания и 99 МБ после установки; первый кадр игры появляется примерно через 0,4 с (Infinix) и 0,75 с (Redmi). Память – около 245–270 МБ.
- Ограничение FPS идёт ровно, когда частота экрана кратна ему: 60 на экранах 120 Гц, 30 – везде; ограничение выше частоты экрана ничего не меняет.

### Сборка из исходников

Понадобятся **Godot 4.7.2** (обычный), шаблоны экспорта, **JDK 17**, **Android SDK** (platform 36, build-tools 36.1.0, NDK 29.0.14206865), **Rust 1.95** с целями `aarch64-linux-android` и `armv7-linux-androideabi`, [`cargo-ndk`](https://github.com/bbqsrc/cargo-ndk) и Python 3. Пути к SDK и JDK задаются в настройках редактора Godot.

```bash
git clone https://github.com/Mahiron-hq/2048.git
cd 2048
python tools/build_native.py host        # движок подсказок на Rust для этого компьютера (редактор и тесты)

# Пакеты для Android: ключ подписи берётся из окружения, в репозитории секретов нет
export ANDROID_HOME=/путь/к/sdk ANDROID_NDK_HOME=$ANDROID_HOME/ndk/29.0.14206865 GODOT=godot
export GODOT_ANDROID_KEYSTORE_RELEASE_PATH=/путь/к/release.jks
export GODOT_ANDROID_KEYSTORE_RELEASE_USER=alias
export GODOT_ANDROID_KEYSTORE_RELEASE_PASSWORD=secret
python tools/export_android.py           # APK arm64, armeabi-v7a, universal и AAB в build/
```

`export_android.py` запускает и конвейер релизов: он собирает библиотеку на Rust для обеих архитектур, ставит шаблон Gradle с закреплёнными контрольными суммами, экспортирует пакеты, подписывает APK схемами v2 и v3 и проверяет сертификат, версию и нативный код каждого пакета.

Тесты: `cargo test` в `native/`, затем `run_tests.gd` и `ui_smoke.gd` в Godot – команды в английском разделе выше. Скриншоты для магазинов и README снимаются с настоящих партий ([`tools/make_screenshots.gd`](tools/make_screenshots.gd)), баннеры, иконка и видео генерируются остальными скриптами в `tools/`.

### Непрерывная интеграция

- **[Tests](.github/workflows/ci.yml)** – на каждый push в main и pull request: форматирование, линты (предупреждения как ошибки), сборка и тесты движка на Rust; `gdlint`; проверка согласованности версии; тесты Godot на Linux с нативным движком, которые падают при любой ошибке скрипта или утечке.
- **[Release](.github/workflows/release.yml)** – по тегу `vX.Y.Z`: тесты, затем сборка без прав на запись (все APK и AAB через [`tools/export_android.py`](tools/export_android.py)), проверка запуска universal APK на эмуляторе Android и только потом публикация: аттестация пакетов и релиз с описанием из [CHANGELOG.md](CHANGELOG.md).
- **[Pages](.github/workflows/pages.yml)** публикует [политику конфиденциальности](https://mahiron-hq.github.io/2048/privacy/) из `PRIVACY.md`.
- **Цепочка поставки:** все actions закреплены на SHA коммитов (обновления предлагает Dependabot, и для Rust-зависимостей тоже), Godot и шаблоны сверяются с суммами SHA-512, Gradle и каждый артефакт Maven – с закреплёнными контрольными суммами, Rust собирается с зафиксированными версиями зависимостей, а пакеты обязаны нести сертификат релизов. Ключ подписи хранится только в секретах окружения `release`.

### Как это устроено

- **`scripts/core/board.gd`** – чистая логика поля от 3×3 до 6×6: ход сообщает сдвиги, слияния и спавн, у плиток стабильные id, ограниченная история отмен проигрывает ходы назад, сохранение разбирается строго.
- **`native/`** – движок подсказок на Rust. В `core` – поле, эвристика рядов и поиск expectimax: углубление по одному уровню, разбор вариантов под корневыми ходами по рабочим потокам со своими таблицами транспозиций, уточнение порога вероятности при запасе времени, остановка по бюджету, отмене или устоявшемуся ответу. `gdext` отдаёт его в Godot как `HintEngine` через godot-rust; `scripts/core/hint_runner.gd` откатывается на решатель на GDScript, если библиотеки нет.
- **`scripts/core/save_store.gd`** – атомарное сохранение в JSON с резервной копией и восстановлением, рекорды и статистика по размерам поля, настройки, текущая партия с историей отмен; старые сохранения переносятся автоматически.
- **`scripts/ui/design.gd`, `palette.gd`, `tile_art.gd`, `motion.gd`** – дизайн-система: токены, цветовые роли, одна отрисовка плиток, масштаб текста и уменьшение движения. Обзор: [docs/DESIGN.md](docs/DESIGN.md).
- **`scripts/ui/board_view.gd`** – анимация ходов и отмен на пуле плиток. Новый свайп посреди анимации мгновенно её доматывает, ввод не теряется.
- **`scripts/app.gd`** – переходы между экранами, масштабирование с учётом ориентации (короткая сторона всегда 720 единиц), тема и язык, время в игре, удержание экрана, фоновые сохранения.
- **`scripts/platform/`** – Android через JNI: вибрация через системный `Vibrator` (виброотклик для касаний, медиа для слияний), запрос частоты экрана, масштаб шрифта, «Убрать анимации», сворачивание приложения.
- **`locale/*.po`** – строки интерфейса с множественными формами.
- Рендерер Compatibility (OpenGL ES 3) – максимальная совместимость с бюджетными устройствами.

### Ограничения

- **iOS.** Проект кроссплатформенный и пресет iOS есть, но для `.ipa` нужны macOS, Xcode и аккаунт Apple Developer, а движок подсказок под iOS пока не собирается.
- Явный запрос частоты работает на Android 11+. На Android 8–10 частоту выбирает система; ограничение FPS работает везде.
- Ни одно приложение не превысит частоту, выбранную в настройках экрана телефона, а некоторые оболочки ограничивают её ещё и для отдельных приложений (например, у Infinix XOS есть свой список). Игра всё равно просит максимум панели и получает наибольшую частоту, которую разрешает телефон.
